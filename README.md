# goyang_dashboard

고양시 가좌·송포 고령자 의료접근성 — **똑버스 도입 검토판**.

정책 판단용 화면이다. 운영 모니터가 아니다.

| 정하는 것 | 달라지는 것 |
| --- | --- |
| 차종 · 도입 대수 · 지정 승차장 수 · 현행(비교 기준) | 탄소배출 · 승차장까지 보행거리 · 대기시간 · 예산 |

```
pip install -r requirements.txt
streamlit run streamlit_app.py
```

## 왜 가좌·송포인가

고양시에서 대중교통 의료접근성이 가장 낮은 군집이다. 저접근 하위 25% 격자의
연결성분 가운데 1순위(대표동 가좌동), **44격자 · 출발점 124 · 고령 946.5명**.
집 앞에서 30분 안에 닿는 의료기관이 평균 **0.20곳**으로 시 평균 61.19곳의
0.32%다. 21격자는 80분을 줘도 0곳이고, 45분을 줘도 절반이 닿지 못한다.
느린 것이 아니라 길이 없다.

## 모형

한 '통행'은 왕복이다. 집→의원, 의원→집 **두 구간**으로 쪼개 센다. 그래야
차량 점유시간과 공차주행이 겹쳐 세어지지 않는다.

- **수요** 고령 946.5명 × 연 30회 ÷ 365일 = 하루 78통행. 고령 의료통행만
  세므로 소요 자원은 **보수적 하한**이다.
- **승차** 지정 승차장. 고령인구를 가중치로 둔 군집 중심을 도로에 붙였다 —
  **임시 가정**이며, 실제 선정에는 보행 접근권·정차 가능 지점 분석이 따로
  필요하다. 목록이 나오면 `sim.designated_stops()` 만 갈아끼우면 된다.
- **합승** 호출 35분·출발 2 km·도착 2.5 km 안이면 한 차에 묶는다(최대 4명).
- **배차** 가장 빨리 도착하는 차량. 직전 하차지에서 승차지까지가 공차다.
- **현행** 가좌·송포에는 갈 수 있는 대중교통이 없다. 이 통행은 지금 택시나
  자가용으로 이뤄지고 있고 그 배출이 비교 기준이다. 무엇으로 보느냐에 따라
  부호가 바뀌어 화면에서 고르게 했다.

배출계수는 환경부 2021년 승인 국가계수, 전력 0.4747 kgCO₂/kWh(소비단).
재차인원·운송원가는 수원시정연구원 2024(광교 똑버스 호출 329,501건).

## 카카오 API 키

`.env.example` 을 `.env` 로 복사하고 키를 넣는다. `KAKAO_REST_API_KEY` 와
`KAKAO_REST_KEY` 둘 다 받는다.

```
KAKAO_REST_API_KEY=발급받은_REST_API_키
```

- 발급: https://developers.kakao.com → 내 애플리케이션 → 앱 키 → REST API 키
- `.env` 는 `.gitignore` 에 있어 저장소에 올라가지 않는다
- Streamlit Cloud 는 `.env` 를 읽지 않는다. **App settings → Secrets** 에
  같은 이름으로 넣는다
- **키가 없어도 돈다.** 국가표준노드링크 최단경로로 물러선다. 두 값의 비는
  표본 50쌍에서 **1.011**이었고, 카카오 소요시간에서 역산한 평균속도는
  31.0 km/h 로 모형 가정 30 km/h 와 맞았다

키를 넣은 뒤 거리행렬을 받아 시나리오를 다시 구우려면:

```
python kakao.py            # 키가 먹는지 확인 (호출 2회)
python build_scenarios.py  # 거리행렬 수집 + 468개 시나리오
```

호출량은 묶어서 줄였다. 승차장↔의원 거리를 `/v1/destinations/directions` 로
한 번에 30곳씩 묻고 응답을 `data/kakao_cache.json` 에 쟁인다. 처음 한 번만
600회 남짓이고, 다시 돌리면 거의 호출하지 않는다.

## 한계

가좌·송포에는 아직 똑버스가 없다. 이 화면의 운행·탑승·탄소는 광교 똑버스
실측 지표로 만든 **추정**이며 고양시의 실제 운행이 아니다. 시드를 고정해
같은 설정이면 언제나 같은 결과가 나온다.
